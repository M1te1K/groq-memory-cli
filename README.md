# CLI-бот с постоянной памятью

Вариант 4 тестового задания: консольный бот на Python, Groq и SQLite. Он запоминает имя, город проживания, профессию/занятие и предпочтения отдельно для каждого пользователя. Факты сохраняются после перезапуска; история разговора хранится только в RAM.

## Установка и первый запуск

Нужны Python 3.11+ с `venv`, Git и ключ Groq для диалога с моделью. Локальные команды работают без ключа. Проверенная версия Python: 3.13.13.

Скопируйте репозиторий и создайте отдельное окружение:

```bash
git clone https://github.com/M1te1K/groq-memory-cli.git memory-agent-cli
cd memory-agent-cli
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.lock
python -m pip install --no-build-isolation --no-deps -e .
cp .env.example .env
```

Команды выше предназначены для macOS/Linux. В Windows PowerShell используйте `py -3 -m venv .venv`, `.\.venv\Scripts\Activate.ps1` и `Copy-Item .env.example .env`; остальные команды с `python` те же. При повторной настройке сохраняйте существующий `.env`.

Создайте ключ в Groq Console в разделе API Keys. Откройте созданный `.env` в текстовом редакторе и вставьте ключ после `GROQ_API_KEY=`. Затем из корня проекта:

```bash
python -m memory_agent --user sergey
```

`requirements.lock` фиксирует прямые, транзитивные, тестовые и сборочные зависимости. `pyproject.toml` описывает пакет, точные прямые зависимости и дополнительную группу `dev`. Установка по lock-файлу выше воспроизводит проверенное окружение. Альтернатива для разработки: `python -m pip install -e ".[dev]"` (транзитивные зависимости при этом выбирает pip).

## Конфигурация

Пример `.env.example` включён в проект и содержит пустой ключ:

```dotenv
GROQ_API_KEY=
GROQ_MODEL=openai/gpt-oss-20b
MEMORY_DB_PATH=./data/memory.sqlite3
GROQ_TIMEOUT_SECONDS=20
```

| Переменная | Назначение |
|---|---|
| `GROQ_API_KEY` | Ключ Groq. При пустом значении доступны локальные команды; обычное сообщение получает «Сервис временно недоступен» |
| `GROQ_MODEL` | Модель для обоих запросов; по умолчанию `openai/gpt-oss-20b`. Для извлечения нужна поддержка строгих Structured Outputs |
| `MEMORY_DB_PATH` | Путь SQLite; по умолчанию `./data/memory.sqlite3`. Относительный путь считается от корня исходников, а не от текущего каталога терминала |
| `GROQ_TIMEOUT_SECONDS` | Таймаут одной сетевой попытки: 1–120 секунд, по умолчанию 20 |

Переменные окружения имеют приоритет над `.env`, включая пустой `GROQ_API_KEY`. После изменения файла перезапустите процесс. Ключ OpenAI не нужен: интеграция использует Groq. При обычном диалоге Groq получает сообщение, факты активного профиля и ограниченную историю.

При запуске CLI показывает абсолютный путь к БД и модель. Каталог данных создаётся автоматически. Рекомендуемый запуск — из корня проекта. Из другого каталога можно указать пути к интерпретатору и исходному `run.py`, например из родительского каталога копии:

```bash
./memory-agent-cli/.venv/bin/python ./memory-agent-cli/run.py --user sergey
```

## Команды и профили

| Команда | Действие |
|---|---|
| `/help` | Показать справку |
| `/memory` | Прочитать факты активного профиля напрямую из SQLite, без LLM |
| `/reset` | Очистить историю текущего профиля в RAM, сохранив постоянные факты |
| `/forget` | Удалить факты, персональные события и историю текущего профиля |
| `/user anna` | Переключиться на другой локальный профиль |
| `/exit` | Завершить процесс; также работают EOF и Ctrl+C |

Профиль выбирается через обязательный `--user` или `/user <id>` и виден в приглашении. ID содержит 1–64 латинских букв, цифр, `_`, `.`, `-`, начинается с буквы или цифры. У каждого профиля отдельные факты и история. Аутентификации нет: любой с доступом к CLI может выбрать любой профиль. Факты и события в SQLite не зашифрованы. Для одного профиля используйте один процесс.

## Проверка памяти вручную

С настроенным ключом выполните:

```text
[sergey] > Меня зовут Сергей, я программист, живу в Казани и предпочитаю чай.
Бот: ...
[sergey] > /memory
... Имя: Сергей
... Профессия/занятие: Программист
... Город: Казань
... Предпочтение: ... чай ...
[sergey] > /reset
История диалога очищена. Сохранённые факты остались.
[sergey] > /exit
```

Это ожидаемый сценарий: формулировки, порядок и ID зависят от модели и прежних записей. Снова запустите `python -m memory_agent --user sergey`, выполните `/memory` и спросите «Как меня зовут?» и «Чем я занимаюсь?». Факты должны остаться, история нового процесса пуста.

Через `/user anna` сохраните другое имя, затем вернитесь к `sergey` и выполните `/forget`. Его `/memory` покажет «Сохранённых фактов нет», а память `anna` останется. `/forget` удаляет также прежние события пользователя без нового персонального события об удалении. Следующая команда `/memory` или сообщение создаёт новые события. Команда действует на текущую БД и RAM этого процесса; резервные копии, история терминала и контекст других процессов остаются вне её управления.

Имя, город и профессия имеют по одному актуальному значению. «Теперь я работаю дизайнером» заменяет профессию с сохранением ID, повтор не создаёт дубль. «Меня зовут Сергей, а тебя?» поддерживается как имя; «Пиши коротко», «Отвечай кратко», «Предпочитаю короткие ответы» — как предпочтения. Цитаты, гипотезы и сведения о других людях не должны попадать в профиль; временное «Я сейчас в Москве» не означает переезд. Проверяйте результат через `/memory`: строгий JSON и локальные проверки не гарантируют правильность понимания любого текста моделью.

## Тесты

В активированном окружении из корня проекта:

```bash
python -m pytest -q
python -m pip check
```

Автотесты работают без сети и API-ключа, используют временные БД. Проверяются сохранение в новом процессе, изоляция пользователей, `/reset`, `/forget`, профессия и миграция старой схемы, откат транзакций, ошибки Groq и продолжение CLI. HTTP-проверки используют настоящий SDK с подставным транспортом; качество живой модели они не подтверждают. Результаты подготовки и сверки: [PUBLICATION_CHECK.md](PUBLICATION_CHECK.md).

Отдельная ручная проверка с настоящим ключом: `python tests/live_smoke.py`. Она использует синтетические сообщения и временную БД, делает 20 логических запросов при полном успехе плюс ограниченные повторы. Требует сети, расходует квоту Groq и останавливается при первом отказе; pytest её не запускает.

## Просмотр логов

Логи хранятся в таблице `events` той же SQLite, отдельного файла логов нет. Поля: `timestamp` (UTC), `user_id`, `event_type`, `payload_json`. Успешный ход записывает `memory.read`, выполненные `memory.add/update/delete` и `turn` с запросом и ответом. `/reset` пишет `history.reset`; `/memory` — `memory.read`. Ошибки отмечаются `turn.error`, `memory.error`, `storage.error`. Служебные события содержат безопасные категории; сырые сетевые ошибки и заголовки авторизации не записываются. Запросы, ответы и факты в событиях — персональные данные. Логи не используются как контекст LLM.

Прочитайте последние события через стандартный `sqlite3` Python (из корня проекта; используется настроенный путь). Режим `mode=ro` не создаёт и не изменяет БД:

```bash
python - <<'PY'
import sqlite3
from memory_agent.config import load_settings

path = load_settings().db_path
with sqlite3.connect(path.as_uri() + "?mode=ro", uri=True) as connection:
    for row in connection.execute(
        "SELECT timestamp, user_id, event_type, payload_json "
        "FROM events ORDER BY id DESC LIMIT 20"
    ):
        print(*row, sep=" | ")
PY
```

В PowerShell этот же Python-код можно сохранить в файл и выполнить из корня проекта. В SQLite-клиенте достаточно запроса:

```sql
SELECT timestamp, user_id, event_type, payload_json
FROM events ORDER BY id DESC LIMIT 20;
```

## Типичные ошибки и ограничения

| Симптом | Что проверить |
|---|---|
| «Сервис временно недоступен» | Пустой/неверный ключ, сеть, таймаут, квоту Groq (429) и модель. Категория/HTTP-статус есть в `turn.error`; локальные команды продолжают работать |
| «Не удалось проверить изменения памяти…» | Повторите факт отдельным явным утверждением и проверьте `/memory`. После двух неудачных извлечений ничего не сохраняется; это отдельная ошибка проверки памяти |
| Ошибка открытия/записи БД | Права на каталог, свободное место, корректность `MEMORY_DB_PATH`, другой процесс. Неудачный ход не показывает неподтверждённый ответ |
| «Некорректная конфигурация» | Непустой путь БД, модель и таймаут в диапазоне 1–120 |
| `No module named memory_agent` / `pytest` | Активируйте окружение, выполните установку и перейдите в корень проекта; для другого каталога используйте `run.py` |
| Кажется, память пропала | Сравните напечатанный путь БД и выбранный `user_id`; проверьте окружение, которое перекрывает `.env` |

Обычный ход использует два запроса Groq: извлечение изменений и генерацию ответа. Изменения и события сохраняются одной транзакцией, затем обновляется история и показывается ответ. Сетевой отказ не меняет факты и историю. Повторы SDK отключены; адаптер делает максимум один сетевой повтор при временной ошибке, с ожиданием 0,5 секунды или `Retry-After` до 2 секунд. Отказ проверки извлечения допускает один дополнительный запрос. Общий ход может занять несколько таймаутов.

Лимиты: сообщение и ответ до 8 000 символов, факт до 500, до 50 фактов на профиль. История ограничена 10 полными парами и 24 000 символами. При открытии старой БД транзакционная идемпотентная миграция добавляет поддержку `occupation`, сохраняя существующие записи.
